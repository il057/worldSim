# 模块 01：角色卡清洗与摄入管线规范 (Ingestion Pipeline)

---

## 1. 概述与核心职责

在 SillyTavern（酒馆）生态中，角色卡广泛存在各种针对人机实时对话特化的杂质数据（如内嵌 HTML/CSS、前端脚本宏、强制尾部状态栏指示词以及强依赖 `{{user}}` 的对话模板）。
摄入管线（Ingestion Pipeline）的核心任务是：
1. **剥离所有前端展示性与控制性脏数据**，还原纯粹的角色文学设定。
2. **解除对外部用户 `{{user}}` 的交互依赖**，将交互动机转写为内在心理执念或背景羁绊。
3. **保留并结构化世界书（Lorebook/WorldBook）**：绝不随意截断或大幅压缩世界书内容，完整归类静态背景与动态触发词。
4. **生成角色自适应作息画像（Circadian Profile）**：基于角色身份、种族与生活习惯，动态提取其作息偏好与休眠阈值。
5. **处理多人卡**：识别多实体并引导选定唯一主视角主角（POV Protagonist），将次要实体自动降维为关系网 NPC。
6. **提供纯表单极简创建通道**：基于 4 个基础维度，通过标准化 Prompt 单次衍生出具备同等深度设定的角色数据对象。

---

## 2. 酒馆卡清洗规则与指导逻辑

AI 开发者在实现清洗模块时，应组织为管道式过滤器（Pipeline Filters），按顺序执行以下剥离操作：

### 2.1 样式与控制标记过滤
- **HTML/CSS 与富文本剥离**：使用正则表达式识别并剔除 `<style>`、`<script>`、`<details>`、`<summary>` 标签及其包含的内容；移除所有裸露的 HTML 容器标签（如 `<div>`, `<span>`, `<p>`, `<br>` 等，替换为合适换行）。
- **酒馆宏与控制标签剥离**：清理 `<START>` 对话标记、前端条件宏（如 `{{random:...}}`、`{{setvar:...}}`）。将 `{{char}}` 占位符统一静态替换为角色自身的真实姓名。
- **状态栏强指令双向剥离**：匹配并剔除“每次回复在末尾附带”、“输出格式必须包含”、`Status_Rule`、`Format_Template`、`{Location, Attire, Time}` 以及所有指示模型打印 ````stat`、````json 或 `[Status: ...]` 状态框的系统提示。该过滤规则同时作用于卡片主体描述与世界书条目。

### 2.2 `{{user}}` 依赖解耦算法
在自主模拟场景中，不存在人类玩家即时输入。若暴力清除 `{{user}}` 会导致角色的社会关系与情感动机空心化。解耦策略分为两级：

1. **直接启发式转换**：
   - 将主谓宾中的 `{{user}}` 转换为角色视角下的客观代词或叙事身份（例如“昔日同行之人”、“不告而别的旧友”或“未曾谋面的雇主”）。
   - 将“等待 `{{user}}` 下达指令”改写为“沉思审视当下的处境与行动目标”。
2. **AI 语义重构（Decouple Rewrite Prompt）**：
   对于角色卡中深度交织的交互设定，指导 LLM 将其转写为角色内生执念。提示词指导规范：
   - 明确告知模型角色当前处于独立演化世界，无人类实时对话参与；
   - 提取原设定中角色对 `{{user}}` 的好恶、依赖或契约，沉淀为一段静态的**人物历史羁绊（Historical Bond）**与**内在核心追求（Inner Drive）**；
   - 严禁输出任何代词“你/用户/玩家”，采用纯正第三人称文学语调。

## 3. 世界书（WorldBook/Lorebook）完整提取与分类

酒馆角色卡的世界书通常承载着完整的架空世界法理、地理与势力设定，体量往往达到数千至上万字。**系统坚决不进行粗暴的字数压榨或截断**，而是按照调用机制进行分类落库：

### 3.1 清洗与垃圾条目剔除
- **状态栏与元指令条目彻底剔除**：若世界书条目标题、触发词或正文包含 `状态栏`、`Status_Rule`、`Format_Template`、`System Prompt`、`Jailbreak` 或指示回复末尾附加特定格式的代码块，判定为纯客户端控制类条目，自动拦截并不予落库。
- 保留所有涉及地理风貌、魔法/科技法则、历史事件、组织势力、物品装备等设定的条目。

### 3.2 世界书 NPC 关系提取与注入
- 当世界书条目标题或正文包含 `NPC_1:`, `Name: ... Relationship: ...` 等人物档案特征时，自动提取结构化社交关系网（姓名、关系类型、好感度、身份背景及对主角态度）。
- 提取后的 NPC 关系展示于前端审查面板，并在角色落库时批量写入 `character_relationships` 社交关系表。

### 3.3 深度分类逻辑
1. **静态全局世界观（Static World Lore）**：
   - 特征：通常标记为常驻生效、无特定关键词触发（`keys` 为空）或声明为背景底色。
   - 调度策略：完整保存在数据库中。在每次裁决与推演时，作为常驻世界底色完整加载（系统 60k 上下文预算可轻松容纳上万字的世界观），为角色的逻辑决策提供充足的世界法则支撑。
2. **动态触发词条目（Dynamic Triggered Lore）**：
   - 特征：包含明确的触发关键词列表（如特定地点名、组织名、魔法术语）。
   - 调度策略：存储在 `world_lores` 表中并建立触发词倒排索引。当推演管线检测到角色当前位置、随身道具、交互 NPC 或裁决涉及相关词汇时，自动将对应的完整条目激活并注入推演上下文。

## 4. 角色自适应作息画像与初始状态衍生 (Circadian & Vitals)

系统坚决杜绝死板的一刀切作息表与硬编码初始数值：

### 4.1 画像与初始状态定义
在角色摄入阶段（清洗或创建时），由 AI 根据角色卡背景推导生成一份自适应运行画像：
- **生理节奏倾向（Chronotype）**：如 `早起型`、`夜行型`、`昼夜无律型`、`无休眠体质`。
- **常规休眠倾向窗口（Typical Rest Window）**：例如 `05:00 - 13:00`。
- **开局微观具体地点（Initial Location）**：基于角色常驻居所或开局情境推导（如“长宁市古董街老宅正堂”），绝不使用通用占位字符串。
- **开局确切虚拟时间（Initial Virtual Time）**：必须包含准确的【公历或纪年年、月、日、时:分】（如“2024年10月9日 20:15”或“天禧三年十月初九日 20:15”），严禁仅输出季节或模糊时辰，后端具备日期校验与自动规整防御。
- **随身背包与紧迫目标**：自适应提取符合职业背景的 3~5 件随身物件与 2~3 条紧迫目标。

## 5. 多人角色卡识别与降维策略 (POV Protagonist Election)

### 5.1 多实体识别（含世界书人物解析）
- 酒馆多人卡的人设普遍定义在世界书条目中（每个角色一个独立条目，或条目标题包含【角色】/【主角】/POV）。
- 解析引擎全面扫描卡片主体描述与世界书条目，智能提取并识别出所有并列的主角候选实体。
- 用户交互：前端以新拟态弹窗呈现所有检测到的候选实体，**仅供用户通过单选按钮选择唯一的主视角主角（POV Protagonist）**。

### 5.2 降维处理机制
选定主主角后，其余实体自动降维为与主角绑定的强关联 NPC：
- **主角实体**：承载核心状态看板、三层记忆与自主推演镜头，作为故事演化的绝对有限视角焦点。
- **降维 NPC**：提取其姓名、身份特征与对主角的初始态度，写入社交关系表（`character_relationships`）。

## 6. 导入前全维度审查与手动微调系统 (Pre-Import Inspector)

摄入管线坚决不进行黑盒强制落库，解析完成后向用户提供 4 维度的新拟态深度微调面板：
1. **人设与执念**：角色姓名、头衔、内在执念与**全量不截断的完整人设**（支持自由增删与修饰）；
2. **生理与初始状态**：开局地点、虚拟时间、健康值滑块、精力值滑块、即时心理、作息画像、背包物品增删及目标增删；
3. **NPC 关系网**：可视化查看所有提取到的 NPC 关系，支持编辑姓名、好感度与背景，支持手动新增或移除 NPC；
4. **世界书设定**：清晰展示已保留的干净世界书条目，支持动态/静态类型切换、触发词修改以及条目增删。

落库时，系统以用户最终确认微调后的全部参数为准统一提交持久化。

## 6. 极简表单 AI 衍生通道 (Quick Character Generator)

针对无酒馆卡的用户，前端仅提供 4 个单选/简短输入维度：
1. **角色名称（Name）**
2. **社会身份（Role/Occupation）**
3. **性格底色（Archetype/Trait）**
4. **开局处境（Initial Situation）**

AI 开发者在此应设计一次性结构化衍生服务，根据上述 4 个维度一次性生成：
- 标准化角色性格底色与核心执念；
- 符合职业与背景的初始状态（健康度、精力值、初始背包物品、开局前 2 个紧迫目标）；
- 对应的自适应作息画像（Circadian Profile）；
- 2~3 条初始记忆碎片（用于充实历史背景）。
产出的对象直接兼容酒馆卡清洗后的标准角色实体格式，统一落库。

## 7. PNG 角色卡内嵌解析与头像提取规范

系统全面兼容 SillyTavern 与主流酒馆生态的标准 PNG 角色卡（内嵌元数据）：
1. **二进制 Chunk 检索**：服务端解析 PNG 字节流中的 `tEXt`、`zTXt`、`iTXt` 数据块，定位关键词为 `chara` 或 `ccv3` 的内嵌数据；
2. **Base64 解码与反序列化**：对数据段进行 Base64 解码并提取 UTF-8 JSON 角色卡主体与世界书；
3. **高清头像无缝保留**：直接将上传的 PNG 编码为 `data:image/png;base64,...` 数据 URL，写入角色的 `avatar_url` 属性中，确保在 UI 看板、角色名录与弹窗中无缝呈现。
