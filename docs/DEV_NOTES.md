# 虚拟世界模拟器开发随笔与演进手记 (docs/DEV_NOTES.md)

本文档记录了 WorldSim 虚拟世界推演系统在核心设计孵化、交互界面重构、双步推演管线调优以及底层提示词工程演进过程中的关键问题、决策思考与开发手记。

---

## 1. 界面与交互演进手记 (UI/UX Evolution)

### 1.1 原型萌芽：顶栏拥挤与多端适配困境 (2026-10-09 12:54)

![初始布局：所有操作堆叠在顶栏](./dev_img/屏幕截图%202026-10-09%20125448.png)

- **暴露问题**：初始阶段为快速打通推演流程，将时间步进按钮、角色管理、突发事件触发器、模型配置等交互控制全量平铺在顶部导航栏（Header）中。一旦视口缩放或置于移动端/窄屏环境下，顶栏按钮迅速拥挤堆叠甚至溢出，破坏了长卷阅读的沉浸感。
- **根因思考**：顶栏应当承担全局状态监控（世界时间、运行模式），而非操作控制台的堆放地。混淆全局状态与场景操作上下文会导致界面承载力迅速崩溃。

### 1.2 交互重构：双抽屉架构与看板常驻化 (2026-10-09 13:10)

![重构布局：抽屉与控制按钮的分离演进](./dev_img/屏幕截图%202026-10-09%20131050.png)

- **演化决策与问题暴露**：引入左侧（系统控制/导航）与右侧（角色详情/看板）双抽屉设计。但在初版抽屉中出现了重复的“新建角色/导入卡片”操作按钮，顶部依然残留了较多操作，破坏了新拟态（Neumorphic）的呼吸感。
- **优化决策**：
  1. **单一操作入口**：彻底移除右侧抽屉内重复的角色新增按钮，收拢至左侧抽屉的角色管理模块；
  2. **观察者状态看板（Status Board）**：移除右侧抽屉内的操作型按钮，将右侧看板确立为持久化视图。宽屏下常驻展示角色当前生理精力（Stamina）、物理坐标、心理状态等指标，让用户随时掌握世界切片而无需频繁触发抽屉。

### 1.3 时钟演进：绝对时间锚定与推演显示去噪 (2026-10-09 18:31)

![时钟引擎演进：移除冗余后缀并强化绝对时间基准](./dev_img/屏幕截图%202026-10-09%20183113.png)

- **暴露问题**：推演过程中 AI 倾向于使用“翌日清晨”、“数小时后”等模糊相对词汇，导致时钟引擎与 SQLite 中的精准时间戳脱节；且每次步进时段落末尾会重复追加 `(+1h)`、`(+6h)` 等机械化标注，打碎了第三人称小说的阅读节奏。
- **优化方案**：
  1. 提示词时钟强契约：在系统提示词中注入精准世界时间基准（年月日时分），强制 AI 基于绝对物理时标展开因果推演；
  2. 废除正文末尾硬编码追加的 `(+xh)` 文本，由前端状态总线直接响应后端推送的最新时间戳，实现静默平滑更新。

### 1.4 社交拓扑：好感度量化与羁绊解耦 (2026-10-09 22:46)

![角色关系拓扑：排版拥挤与信息层级重构](./dev_img/屏幕截图%202026-10-09%20224622.png)

- **暴露问题**：初版 NPC 关系卡片中，姓名、职业、好感度、羁绊描述全挤在单行狭窄区域内，信息密度过载，视觉层次混乱。
- **优化方案**：
  1. 结构化分层：第一行保留姓名与社会身份标识，第二行将好感度抽象为微拟态动态进度条（NeuMeter）；
  2. 羁绊模块解耦：将因果羁绊（Bond）与关键交集独立为卡片子区块，形成清晰的梯队节奏。

- **优化方案**：全面重构手机卡片，继承全局凹凸浮雕与双向阴影设计；无缝接入 DiceBear 矢量头像生成管道，赋予 NPC 具象化面孔。

### 1.6 人设哲学：立体制衡与防激进化纠偏 (2026-10-10 21:10)

![角色生成纠偏：防止过度追求创伤设定的单一倾向](./dev_img/屏幕截图%202026-10-10%20211043.png)

- **暴露问题**：早期摄入 Prompt 过于强调“立体感与戏剧冲突”，导致 AI 产生激进偏见——生成角色的底层执念必定源于“童年创伤/心理阴影/信任危机”。在轻松日常的世界观中强塞黑深残设定，极度违和。
- **优化方案**：引入世界观基调自适应约束，将执念光谱扩展至职业理想、好奇心、日常癖好与生活追求，杜绝创伤模板化。

### 1.7 细节打磨：标签自适应截断与符号去噪 (2026-10-10 22:36)

![排版细节二次优化：防溢出与数值纯净化](./dev_img/屏幕截图%202026-10-10%20223652.png)

- **暴露问题**：AI 生成的 NPC 社会头衔过长导致文本溢出、角色名字换行；正向好感度携带显式 `+` 号（如 `+28`）略显生硬报表感。
- **优化方案**：为身份标签增加 Flex 优雅截断与悬浮 Tooltip；锁定姓名不可换行；格式化逻辑移除正向数值多余的 `+` 号前缀。

### 1.8 视口全屏三栏布局与抽屉贴底演进 (2026-10-11 00:30)

- **暴露问题**：在原本整页流动滚动架构下，外层设置了 `padding-bottom: 4rem`，且左右抽屉依赖 `position: sticky; height: calc(100vh - 85px);`。当中间小说切片长卷（`TimelineLogItem`）滚动到底部时，父级容器到达底部，导致左右两侧的抽屉（导航角色目录与右侧看板）被强行向上推挤，抽屉底端与浏览器视口底端产生近 80px 的巨大空白断层，视觉悬空感严重。
- **优化方案**：
  1. **应用级视口全屏布局**：PC 桌面端将 `.world-app` 收敛为 `height: 100vh; overflow: hidden;`，顶部导航栏高度固定（`flex-shrink: 0;`），下层 `workspace-container` 自适应铺满视口剩余空间；
  2. **三栏独立滚动与抽屉全高贴底**：左右抽屉面板高度统一为 `height: 100%`，始终稳固贴合屏幕底部（保留优雅的 12px 拟态阴影呼吸区），且内部各自自包含独立滚动；
  3. **中间流独立滚动与悬空滚动条去噪**：中间小说正文流（`center-novel-stream`）独立垂直滚动，隐藏原生外部悬空滚动条（`scrollbar-width: none; ::-webkit-scrollbar: none;`），消除卡片与右侧看板之间游离的工业机械线条；
  4. **顶部标头与微光进度条常驻顶端**：将「演化长卷」标头卡片（`stream-top-bar`）作为固定顶层结构与正文滚动区域解耦。标头及底缘的 2.5px 微光渐变阅读进度线（`read-progress-track`）**始终常驻在顶部**，正文卡片向下滚动时从标头下方穿过，进度条随阅读深度平滑生长，永不随滚动滚出视口；
  5. **解除大屏居中限制以全宽贴边**：移除 `.workspace-container` 原有的 `max-width: 1720px` 与居中外边距，在大屏（1920px+）下左右抽屉完美贴紧视口边缘，与顶部 Header 的两端像素级对齐；
  6. **正文与抽屉底色一致性修复**：修复了 `TimelineLogItem` 样式中私自硬编码覆盖的冷白底色 `#f0f3f8`，统一回归全局变量 `var(--neu-surface)`（`#e6e9ef`），消除中间卡片与两侧抽屉的色温色差，恢复新拟态同一材质的光影沉浸感。

- **暴露问题与痛点分析**：
  1. **设置项纵向膨胀与小窗口局促**：随着系统配置与采样参数不断丰富（深浅外观模式、7 款强调色与自定义 Hex 拾色器、LLM Base URL、API Key、可用模型动态探测与下拉、推演采样折叠卡片、时钟步长控制等），旧版设置弹窗的纵向长度大幅增加，在原本局促的 Modal 浮层内部被迫产生多重内外滚动条，极度拥挤压抑；
  2. **暗色全屏遮罩（Overlay Backdrop）严重阻断视觉感知**：旧版采用全屏居中 Modal 弹窗方案，呼出弹窗时会在全屏覆盖一层灰黑色的磨砂遮罩（Backdrop Blur）。当用户在设置弹窗中切换浅色/深色/跟随系统模式，或尝试挑选 7 种主题强调色（Accent Color）时，整站的主背景色、左侧目录、中间小说长卷卡片与右侧看板均被遮罩暗化阻隔，用户根本无法实时感知全站实际的色彩搭配与光影质感，改色操作沦为“盲调”，必须每次手动关闭弹窗才能查验整体视觉效果；
  3. **打断沉浸式阅读流**：世界书与文风提示词同样受限于 Modal 弹窗架构，每次查阅背景条目或调整小说叙事风格时，突兀弹出的遮罩层强行打断了长卷小说的沉浸式阅读心流。
- **重构方案与优化实践**：
  1. **彻底移除浮层遮罩（Zero Overlay Architecture）**：将「系统设置与外观」、「世界书与法则条目」、「文风与提示词工坊」三大核心面板彻底剥离独立 Modal 弹窗，改为沉浸式原位与侧栏嵌入呈现，实现全局 0 遮罩、0 阻隔；
  2. **右栏常驻原位化（`SystemConfigPanel`）**：点击顶栏「设置」按钮时，直接在右侧常驻面板区域（原角色即时生存看板）内平滑原地切替为系统设置面板。设置项拥有专属整高度平滑滚动视口，更关键的是——用户在右侧调换浅色/深色模式及 7 款强调色（经典靛蓝、极光湖蓝、翡翠青碧、琉璃琥珀、绯红蔷薇、暮光罗兰、玄石冷墨）或输入十六进制自定义色彩时，左侧导航、中间小说长卷及顶栏 100% 毫无遮蔽、即时响应并一览无余，主题切换与改色体验真正实现“所见即所得”；
  3. **中间视口原位工作台（`WorldLoreView` & `PromptEditorView`）**：将「世界书」与「文风提示词工坊」作为全宽原位工作台，直接在中间主视口区域（`center-novel-stream`）平滑展开；利用 Vue 的 `v-show` 机制挂载，工坊与小说长卷相互切换时 0ms 闪避、无损保留长卷已滚动的阅读位置；世界书单列自适应展开与提示词分栏排布均获得极其充沛的视口空间，彻底告别小弹窗的局促感。

## 2. 核心管线与底层提示词工程演进 (Pipeline & Prompt Architecture)

### 2.1 为什么坚持 Pass 1 + Pass 2 两步解耦？
在系统设计初期，最直观的做法往往是单次 Prompt 让大模型“既计算主角身心状态，又输出文学描写”。但测试表明这会导致严重隐患：
1. **注意力分散与逻辑崩盘**：LLM 在同时兼顾数值逻辑判定（精力增减、物品获取、时间推移、关系演变）与高质量文学描写时，往往顾此失彼。到了推演后期，容易发生幻觉或违背世界因果律；
2. **两步各司其职**：
   - **Pass 1（衡律之神 Arbitrator）**：纯理性逻辑机器。只负责大纲、因果裁决、作息决策、目标增损以及输出合法的 State Delta JSON。不写文学修辞；
   - **Pass 2（见证之神 Storyteller）**：纯文学叙事大师。以 Pass 1 的客观事实骨架（Plot Beat）和感官线索为地基，以第三人称有限视角完成纯粹文学润色。

### 2.2 文风框架与文学技法补丁库
- **引入初衷**：如果不对文风进行专项系统工程指导，AI 写出的文本无论放在什么世界观下，其用词、句式和语气其实都高度雷同（典型的 AI 通用小说腔调）。为了让世界真正生动灵动，系统引入了原创的 12 种世界模拟文学风貌（东方素描、生活轻喜、黑色幽默、戏谑发疯、日常钝痛、感官漫游、慢调光影、沉郁庄严、青涩时光、诡谲志怪、炉火轻奇等，以及自由自适应匹配），用户可根据不同世界观自由切换。
- **文学技法补丁（Writing Patches）**：针对 AI 写作的常见通病注入精准免疫抗体：
  - *小说张力与事件驱动*：严禁整篇文字在死物垃圾上做无意义显微镜描写（如反复捏易拉罐、抠塑料外壳、看尘埃飘落），强制每一段都有事件在实质发生；
  - *主角意志与动机连贯*：严禁无目的空心发呆，角色每一步都受其内核驱使；
  - *客观白描*：用具体动作与现实抉择替代抽象的情绪定性；
  - *活人生态对白*：对话充满试探、机锋与性格棱角，拒绝变成设定解说机器；
  - *拒绝段尾归纳*：严禁在段末以说书人姿态强行升华总结哲理鸡汤。

### 2.3 文风名家标杆注入与同角色多文风差异化实测 (Style Variations Benchmark)

- **痛点反思**：早期版本中，虽然规划了 12 种文风，但提示词主要采用抽象文学形容词（如“静水流深”、“幽冷浓郁”），缺乏具象的文学标杆，导致大模型生成时极易滑向千篇一律的通用 AI 腔调，用户切换不同文风时感知差异微弱；
- **标杆名家与典籍注入方案**：在 `STYLE_PRESETS` 提示词中为每种文风精准注入文学大师及其经典代表作（如汪曾祺、卡夫卡、陀思妥耶夫斯基、雷蒙德·卡佛、爱伦·坡等），并明确下达句式长短节律与反向禁令；同时在 Pass 2 User Prompt 结尾施加最高权重的“临门一脚”执行指令；
- **同角色多文风实测对比（角色：林桑 · 断网的第四天灾候选人）**：

| 文风 A：诡谲志怪 (`gothic_shadow`) | 文风 B：戏谑发疯 (`mad_outburst`) |
| :---: | :---: |
| ![诡谲志怪文风开场白](./dev_img/屏幕截图%202026-10-11%20205345.png) | ![戏谑发疯文风开场白](./dev_img/屏幕截图%202026-10-11%20205459.png) |

- **开场白文本对比与文学肌理剖析**：
  1. **【诡谲志怪】（对标：蒲松龄《聊斋志异》笔意、芥川龙之介《罗生门》、爱伦·坡）**：
     > *“昏鸦隐没，暮色如泼浓墨。古铁杉林根虬结处，青苔泛着惨淡的幽荧，湿腐酸气混着泥腥在晚风里横冲直撞。林桑半隐在庞杂的老树根后，怀中紧紧抵着那只兔子印花抱枕，指骨因用力而泛出青白。对面那老叟身披滥褛粗麻，须发丛生若枯蓬，嘴里嘶嘶怪叫，双臂乱舞如中邪魅……”*
     - **笔法解析**：全篇充满古雅洗练的冷艳张力与异物感。语言收敛，多用冷冽动词与物象（昏鸦、泼墨、铁杉、青苔幽荧、鸟爪枯手、金石摩擦、霜雪森冷长剑）；异界交流被具象化为以薄荷糖置换幽蓝苦草，通感描写细腻如游丝细刺钻入舌苔，压迫感在残阳与剑锋之间静默悬停。
  2. **【戏谑发疯】（对标：陀思妥耶夫斯基《地下室手记》、太宰治《人间失格》、恰佩克）**：
     > *“电量剩余百分之七的智能手机静静躺在卫衣口袋里，宛如一块正在宣告现代文明寿终正寝的黑色墓碑。林桑紧紧抱着她那只印着褪色兔子的纯棉抱枕，面部神经在微寒晚风里抽搐得如同接触不良的电路板。站在她面前的三米开外，是个身披脏污亚麻长袍的老头……太体面了，简直体面得让人想当场上吊。”*
     - **笔法解析**：理智与体面在现实绝境下剧烈崩解。主角在维持现代文明人的体面社交与彻底精神摆烂之间激烈撕扯；比喻充满尖刻荒诞的现代自嘲（黑色墓碑、接触不良的电路板、滚水沸腾的乱码、新手村武力NPC）；老学士野蛮粗暴抠开嘴塞绿泥与误当发癔症的错位呼喊，将崩溃感与黑色幽默推向极致，节奏急促颠簸，鲜活生动。

### 2.4 字数控制的哲学：推荐引导而非死板卡死
- **设计考量**：不同用户对推演的节奏偏好截然不同。有的希望快速高频步进（精炼短切片 300~500 字），有的希望获得正统长篇阅读体验（标准 500~800 字，或深度长卷 800~1200 字）。
- **软约束认知**：在提示词中必须明确，大模型生成内容具有天然的创造性与不确定性，字数限制本质上是“推荐字数 / 期望引导区间”。生成内容受情节密度影响，略多或略少于设定区间属于正常的文学呼吸，系统不宜采取生硬机械的暴力截断。

### 2.5 文风预设的二次重构与去冗余（轻快欢脱与市井烟火的诞生）
- **冗余反思**：在早期的 12 种文风预设中，`subtle_melancholy`（日常钝痛）与 `cinematic_retro`（慢调光影）在情绪调性上严重重叠，均偏向克制留白与物哀沉郁；而 `stream_flow`（感官漫游）在沙盒实际测试中由于意识流跳跃性过强，容易稀释客观世界的情节推进力。同时，原有体系中明显欠缺适合大众世界观的明快喜剧感与市井群像氛围；
- **重构流派**：
  1. **轻快欢脱 (`light_witty`)**（对标：特里·普拉切特《碟形世界》、J.K.罗琳早期校园笔触）：短句明快干脆，充满少年化拌嘴、机锋吐槽与意外频出的小滑稽，扫除沉重苦大仇深感，大幅增强校园日常与轻快冒险的观赏趣味；
  2. **市井烟火 (`bustling_hearth`)**（对标：老舍《茶馆》、金庸武侠市井篇、金宇澄《繁花》）：充满真实社会的生民起居与热气腾腾的底噪，聚焦食堂长桌、茶摊酒肆与喧闹街市，让小人物的狡黠与温存包裹主角行动；
  3. **冷调光影 (`cinematic_retro`)**：将原日常钝痛与慢调光影统合优化为纯正的电影胶片质感，去除同质化词藻。

## 3. 前端视界之外的推演细节 (Hidden Engine Mechanisms)

### 3.1 在场 NPC 多人关系特化（避免“世界围着主角转”）
这是用户在前端界面上看不到、但后端推演管线至关重要的提示词注入细节：
- 当判定当前物理空间有 NPC 在场（或有来客/交谈对象）时，管线会动态注入专属的多人关系特化提示词；
- **核心法则**：坚决避免“全世界围着主角转”的单向独角戏。每位在场角色都拥有独立的生存立场、核心利益与道德底线。事件是由“个人选择—群体反馈”连锁推进的，人人有戏、彼此成局，NPC 绝非单向响应主角的工具人。

### 3.2 动态社交拓扑扩充：新认知角色的自主沉淀机制
- **破除固有小圈子**：在很多模拟器中，主角推演了几百轮后，认识的人永远只有世界初始化时写好的那两三个角色，世界显得死寂狭小。
- **自主识别与深刻印象准则**：在 Pass 1 裁决中，赋予了 AI 自主识别并结识新角色的权限（`relationship_delta.new_npcs`）。同时设定了严格的结识门槛——随口搭话的路人甲、打照面的背景龙套绝不入库，唯有主角对其产生深刻印象、具备明确姓名且拥有后续持续交集潜力的关键人物，才会正式沉淀进主角的人际关系网中。

## 4. 拟真生态与自转节律探索 (Living World & Pacing)

### 4.1 为何在沙盒中引入拟真手机系统？
- **沉浸感必然**：现代与近未来背景下，人的生活早已与手机深度绑定。微信消息、语音、转账记录、朋友圈动态、匿名论坛发帖，是当代人际交往与信息获取最真实的切片；
- **跳出“小说生成器”的思维定势**：WorldSim 的定位从一开始就不是传统的死板网文生成器，而是一个自运转的沙盒世界。既然作为模拟世界，为什么不多做一些跳出常规文本框的、充满趣味与拟真感的探索？

### 4.2 自由续写（智能续写）与真实时间尺度约束
- **续写初衷**：在单步 1 小时或快进时，用户经常会遇到刚刚触发了一件极感兴趣的突发事件，但一旦点击下一步（+1h），AI 往往在段落开头用一两句话把刚才的事草草交代收尾，极度扫兴。智能续写允许用户在不强行跳转时间的前提下，让 AI 就当前焦点事件继续自然推演展开。
- **时间节律与尺度指引**：为了杜绝“时间才过去 1 小时，主角吃了饭洗了澡甚至还拖了个地”的时空膨胀荒谬情节，引擎引入了“完整行动单位尺度”指引，AI 自主研判推进 0.5h、1h 还是半天，铺垫时放慢展开细节，交锋时紧扣危机，维持真实的物理重力感。

### 4.3 突发事件（变数之引）去极端化与世界观自适应
- **早期的偏激教训**：在最初构思突发事件提示词时，为了追求强戏剧张力，提示词编写得过于偏激激进。在实际测试中，甚至出现过普通校园青春背景下，平地冒出一个“神秘杀手暗杀主角”的荒谬出戏情节。
- **优化与自适应**：全面重构了突发事件构思引擎，要求其必须严密契合当前世界观题材（校园、职场、修仙、末日等）与即时微观情境。突发事件（如失物招领、突击检查、暴雨滞留、错收快递、临时调派）的使命是自然打破当前稳态、注入生动波澜，绝非为了冲突而强行摧毁日常世界观。

## 5. 生命认知与日常底噪演进实战 (Age Behavioral Dynamics & Ecosystem Grounding)

### 5.1 年龄不等于粗暴性格标签：从“11岁冷酷老成特工”谈起
- **长程测试暴露的问题**：在对 11 岁拉文克劳一年级新生萝西·瓦伦泰进行 20 刻长程推演分析时，我们发现角色表现得过于“冷酷成熟”，甚至如同历经沧桑的冷血特工；无论遇到任何危险或变故，角色全程心如止水、面无波澜，毫无同龄人应有的生理与情绪联动，也几乎看不到上课、就餐等校园日常；
- **年龄行为认知锚点（Age Behavioral Dynamics）的提出**：
  1. **仲裁优先级原则**：角色的核心性格/身世设定决定「想要做什么」，年龄规则仅决定其「如何权衡后果与掩盖破绽」。若角色存在跨年龄特质（如童年杀手、百岁顽童），保留其性格特质，但通过其应对代价的方式来体现年龄机制；
  2. **四阶段行为分流机制**：
     - **幼少期（< 16 岁）**：世界以自我为参照。掩饰手段单一即时，面对完全失控局面第一反应是短暂认知停滞（发懵）或本能生理防御；情绪与身体高度联动，缺少长线伪装阈值；做蠢事心虚慌乱，得逞暗爽与好胜心；
     - **青年前期（16 ~ 25 岁）**：自我意识极强，理想与现实剧烈拉扯，最易产生言行分裂感。少年老成型的本质是高度紧绷的拟态与克制，极端受挫仍会暴露未受岁月磋磨的硬撑痕迹、道德洁癖或固执偏执，而非大彻大悟；
     - **壮年中期（26 ~ 50 岁）**：现实锚定与利益权衡，掌握稳定的社交面具与情绪缓冲带，深知后续代价，极少单纯为口舌之快消耗能量；
     - **暮年 / 长生者（> 50 岁）**：低能耗与去中心化，时间尺度感与常人不同，极高耐受阈值与钝感，极少被突发事件牵着鼻子走，少有无意义的自我证明；
  3. **未解析周岁时的全域兜底**：若架空历法或人设未成功解析出数字周岁，严禁模型将角色当作无年龄的冰冷符号，必须依据身份生态位（学生/学徒/实习生/老宿老）主动推断生命阶段并贯彻上述机制。

### 5.2 从全量大Prompt到按生命阶段精准分发（Token 极致精简）
- **初期粗放方案的缺陷**：在最初实现时，我们将 4 个年龄阶段的大段 Prompt 一股脑全量塞入 System Prompt，导致单轮推演白白浪费近千 Token，既拉长了生成延迟，又分散了模型对目标年龄段的注意力；
- **动态切片分发重构**：改造为根据角色生日或人设动态计算其实时周岁，由 `get_age_stage_key` 判定当前所处的阶段 key（`child` | `youth` | `adult` | `elder` | `fallback`），系统仅提取对应单一阶段的紧凑提示词片段注入 System Prompt，使年龄相关提示词的 Token 开销骤降约 75%。

### 5.3 实战样本三阶段演进对比（从冷血特工、念白出戏到纯粹白描）

为了让读者直观感受这一规则迭代对大模型叙事质感带来的真实蜕变，以下摘录推演日志中针对拉文克劳一年级新生**萝西·瓦伦泰（11周岁）**的三阶段真实生成对比：

#### 阶段一（Tick #020 早期无年龄规则约束）：冷酷老成特工腔 (Bad Case)
> *“那扇沉重的厚栎木门前，青铜鹰形门环在穿堂烈风中冷硬地吐出诘问：‘存在物能否在被抹去其形式的同时，保留其本质？’萝西连半秒喘息都没留给发软的肺叶，右手死死按着冒烟的侧兜，迎着门环冷冷吐字：‘形式即本质在时间里的投影，抹去投影，本质便退化为未发生的潜能——它既不存在，也无所保留。’……她面无表情地抓起铸铁冷凝钳，两指死死掐住早已备好的矿脂引信，迎着喷溅的灼热白烟，将带有坚韧硬壳的引芯钝端蛮横地压进正中央那枚最暴烈的火斑内孔。……黄铜锁舌应声咬死，嘴角无声地咧开一道极硬的笑意。”*
- **笔法缺陷剖析**：面对即将炸膛的违禁黑市火灰蛇卵，一个 11 岁的小女孩全程“面无表情”、“冷冷吐字”、“蛮横咬合”，嘴角咧开“极硬的笑意”。这里完全退化成了千篇一律的杀伐果断 veteran 特工腔，看不到半点孩子做坏事的心虚、对校规惩罚的忌惮或身体的本能慌乱。

#### 阶段二（Tick #021 初步全量注入年龄规则）：旁白念白报年龄出戏 (Bad Case)
> *“十一岁的神经到底被逼到了窄处。萝西迎着多拉那双发直的眼睛，喉头猛地一哽，短暂的发懵让她脸上掠过一丝被当场抓现行的慌乱。但好胜心随即硬生生顶了上来，她猛地扬起下巴，一把抓起桌角摊开的羊皮纸小册子甩在膝头，生硬地抢白：‘闭嘴，多拉！它现在比斯内普的鼻梁还冷，引信吃死了矿脂，连一星火苗都吐不出来！’她吸了一口气，将那本密密麻麻记满诡辩公式的笔记推向多拉颤抖的鼻尖，语调又快又硬，‘看清楚，这是后半学期解构门环的推论笔录……只要背熟，就算门环问你时间是实存还是虚妄，你也能三秒进门，再也不用在走廊受冻等级长来救。’……‘成交。不在塔楼。’萝西飞快地接口，掌心在袍子上蹭掉冷汗，嘴角终于忍不住浮起一丝得逞的微翘。”*
- **迭代进步与新痛点**：角色的情绪和肢体开始鲜活联动（被撞破时的短暂发懵心慌、死要面子的抢白、得逞后的微翘嘴角），但开篇出现了致命问题——**大模型直接在正文第一句念白设定：“十一岁的神经到底被逼到了窄处”**。这是最典型的“Telling instead of Showing”，旁白以全知上帝视角替读者总结年龄，不仅出戏，更显拙劣。

#### 阶段三（Tick #022 精准单阶段按需注入 + Show Don't Tell 铁律）：纯粹动作神态与生态嵌合 (Good Case)
> *“抽屉底部的黄铜目镜筒被一把夺过来时，多拉单薄的背脊猛地撞在衣柜门上，发出沉闷的受力声……多拉抢先一步抓起桌上的旧羊皮纸，神经质地挥动袍袖驱散焦烟，又手忙脚乱地将一小瓶薄荷墨水打翻在桌角，用冲鼻的清凉草药味死死盖过残留的火星焦苦。*
> *城堡深处的正午铜钟在此刻沉闷地撞响，悠长的钟声穿透高空烈风，震得铅框玻璃嗡鸣颤抖。萝西顺手将彻底冷却咬死的黄铜圆筒滑入斗篷内衬暗袋，硬质金属带着扎实的坠感，冰凉地顶住肋骨下沿。她迅速抚平袍角褶皱，顺手扶正领口微歪的拉文克劳铜质校徽，原本冷硬的下颌在拉开厚重栎木门的瞬间骤然松弛。多拉抱紧了那本摊开的大字本草药笔记，深吸一口气压下发颤的下巴，两人迈着挑不出半点破绽的乖巧步子，并肩滑入了走廊略显清冷的阴影之中。”*
- **笔法解析**：全篇**零出现**“十一岁”、“少年/孩童”等任何定性词句，完全贯彻了 **【去设定定性与去年龄报数铁律 (Show, Don't Tell)】**。小巫师做完违禁武器后“神经质甩袍袖驱散焦烟”、“手忙脚乱打翻薄荷墨水掩盖火药味”，正午开餐钟声鸣响后“抚平袍角、扶正校徽、抱紧草药课笔记、瞬间切换成乖巧新生步伐”——所有的年龄心智、同伴共谋、即时掩饰与校园生活底噪，全部自然溶解在客观动作与神情之中，沉浸感达到最佳。

### 5.4 去脱产化：社会生态位与日常底噪（上课/工作/就餐）的有机嵌合
- **“脱产潜行特工”的虚假感**：在沙盒推演中，若角色全天候 24 小时不吃不喝不上课、时刻在暗中调查行动，世界就会沦为悬浮的舞台布景；
- **生活是冒险与破局的物理容器**：确立生态位锚定法则与**插缝行动准则（Subversive Daily Life）**。学生必须面对课程、食堂与级长巡查；学徒必须面对工坊与师傅；职员必须面对打卡与通勤。角色的秘密计划与发明，必须有机嵌套在这些不可撼动的日常生活底噪的缝隙之中推进。

## 6. 长程稳定性自动化验证与单文件离线评测报告 (100-Tick Verification & Standalone HTML Report)

### 6.1 长程推演自动驱动器与断点继承 (`auto_driver.py`)
- **验证 100 刻故事一致性的现实难题**：100 刻推演需要调用 200 次 API，若人工在前端逐轮点击不仅极其耗时，且中途出现偏差难以反复验证。因此我们设计了基于真实状态机的自动化驱动脚本；
- **戏剧节律与生理驱动**：驱动器并非无脑单步前进，而是根据角色即时精力（低于 20 自然就寝）、情节焦点（智能续写 vs +1h 微步进）与每 5~10 刻的戏剧波澜（突发事件观察信号）交替驱动，模拟真实读者的长程沙盒观察；
- **断点继承与名字消歧**：支持 `--name` 模糊检索角色与同名多候选交互式选择，自动继承前序批次的日志详情（耗时、决策归因、背包增损与精力流转），确保 20 刻推进到 40 刻或 100 刻时信息绝不丢失。

### 6.2 离线化单文件独立 HTML 评测报告 (`report_generator.py`)
- **展示与汇报诉求**：为了向面试官或技术评审直观展示长篇故事的推演质量，开发了无需外部网络依赖、纯内嵌 CSS/SVG 的单文件 HTML 报告生成器；
- **四大核心板块**：
