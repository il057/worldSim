# 虚拟世界模拟器开发随笔与演进手记 (docs/DEV_NOTES.md)

本文档记录了 WorldSim 虚拟世界推演系统在核心设计孵化、交互界面重构、双步推演管线调优以及底层提示词工程演进过程中的关键问题、决策思考与开发手记。

---

## 1. 界面与交互演进手记 (UI/UX Evolution)

### 1.1 原型萌芽：顶栏拥挤与多端适配困境 (2026-10-09 12:54)

![初始布局：所有操作堆叠在顶栏](./dev_img/屏幕截图%202026-10-09%20125448.png)

- **暴露问题**：初始阶段为快速打通推演流程，将时间步进按钮、角色管理、突发事件触发器、模型配置等交互控制全量平铺在顶部导航栏（Header）中。一旦视口缩放或置于移动端/窄屏环境下，顶栏按钮迅速拥挤堆叠甚至溢出，破坏了长卷阅读的沉浸感。
- **根因思考**：顶栏应当承担全局状态监控（世界时间、运行模式），而非操作控制台的堆放地。混淆全局状态与场景操作上下文会导致界面承载力迅速崩溃。

### 1.2 交互重构：双抽屉架构与看板常驻化 (2026-10-09 13:10)

![重构布局：抽屉与控制按钮的分离演进](./dev_img/屏幕截图%202026-10-09%20131050.png)

- **演化决策与问题暴露**：引入左侧（系统控制/导航）与右侧（角色详情/看板）双抽屉设计。但在初版抽屉中出现了重复的“新建角色/导入卡片”操作按钮，顶部依然残留了较多操作，破坏了新拟态（Neumorphic）的呼吸感。
- **优化决策**：
  1. **单一操作入口**：彻底移除右侧抽屉内重复的角色新增按钮，收拢至左侧抽屉的角色管理模块；
  2. **观察者状态看板（Status Board）**：移除右侧抽屉内的操作型按钮，将右侧看板确立为持久化视图。宽屏下常驻展示角色当前生理精力（Stamina）、物理坐标、心理状态等指标，让用户随时掌握世界切片而无需频繁触发抽屉。

### 1.3 时钟演进：绝对时间锚定与推演显示去噪 (2026-10-09 18:31)

![时钟引擎演进：移除冗余后缀并强化绝对时间基准](./dev_img/屏幕截图%202026-10-09%20183113.png)

- **暴露问题**：推演过程中 AI 倾向于使用“翌日清晨”、“数小时后”等模糊相对词汇，导致时钟引擎与 SQLite 中的精准时间戳脱节；且每次步进时段落末尾会重复追加 `(+1h)`、`(+6h)` 等机械化标注，打碎了第三人称小说的阅读节奏。
- **优化方案**：
  1. 提示词时钟强契约：在系统提示词中注入精准世界时间基准（年月日时分），强制 AI 基于绝对物理时标展开因果推演；
  2. 废除正文末尾硬编码追加的 `(+xh)` 文本，由前端状态总线直接响应后端推送的最新时间戳，实现静默平滑更新。

### 1.4 社交拓扑：好感度量化与羁绊解耦 (2026-10-09 22:46)

![角色关系拓扑：排版拥挤与信息层级重构](./dev_img/屏幕截图%202026-10-09%20224622.png)

- **暴露问题**：初版 NPC 关系卡片中，姓名、职业、好感度、羁绊描述全挤在单行狭窄区域内，信息密度过载，视觉层次混乱。
- **优化方案**：
  1. 结构化分层：第一行保留姓名与社会身份标识，第二行将好感度抽象为微拟态动态进度条（NeuMeter）；
  2. 羁绊模块解耦：将因果羁绊（Bond）与关键交集独立为卡片子区块，形成清晰的梯队节奏。

### 1.5 拟真系统：手机卡片新拟态化与动态头像接入 (2026-10-10 17:30 ~ 17:35)

| 初版：风格割裂 | 优化版：新拟态融合与 DiceBear 头像 |
| :---: | :---: |
| ![初版手机系统 UI 风格割裂](./dev_img/屏幕截图%202026-10-10%20173053.png) | ![优化后手机系统与微拟态完美融合](./dev_img/屏幕截图%202026-10-10%20173544.png) |

- **暴露问题**：新增手机交互功能（私信、转账、论坛）后，初版采用了扁平化简陋对话气泡，与全站新拟态立体阴影质感严重割裂，且 NPC 缺乏视觉形象。
- **优化方案**：全面重构手机卡片，继承全局凹凸浮雕与双向阴影设计；无缝接入 DiceBear 矢量头像生成管道，赋予 NPC 具象化面孔。

### 1.6 人设哲学：立体制衡与防激进化纠偏 (2026-10-10 21:10)

![角色生成纠偏：防止过度追求创伤设定的单一倾向](./dev_img/屏幕截图%202026-10-10%20211043.png)

- **暴露问题**：早期摄入 Prompt 过于强调“立体感与戏剧冲突”，导致 AI 产生激进偏见——生成角色的底层执念必定源于“童年创伤/心理阴影/信任危机”。在轻松日常的世界观中强塞黑深残设定，极度违和。
- **优化方案**：引入世界观基调自适应约束，将执念光谱扩展至职业理想、好奇心、日常癖好与生活追求，杜绝创伤模板化。

### 1.8 视口全屏三栏布局与抽屉贴底演进 (2026-10-11 00:30)

- **暴露问题**：在原本整页流动滚动架构下，外层设置了 `padding-bottom: 4rem`，且左右抽屉依赖 `position: sticky; height: calc(100vh - 85px);`。当中间小说切片长卷（`TimelineLogItem`）滚动到底部时，父级容器到达底部，导致左右两侧的抽屉（导航角色目录与右侧看板）被强行向上推挤，抽屉底端与浏览器视口底端产生近 80px 的巨大空白断层，视觉悬空感严重。
- **优化方案**：
  1. **应用级视口全屏布局**：PC 桌面端将 `.world-app` 收敛为 `height: 100vh; overflow: hidden;`，顶部导航栏高度固定（`flex-shrink: 0;`），下层 `workspace-container` 自适应铺满视口剩余空间；
  2. **三栏独立滚动与抽屉全高贴底**：左右抽屉面板高度统一为 `height: 100%`，始终稳固贴合屏幕底部（保留优雅的 12px 拟态阴影呼吸区），且内部各自自包含独立滚动；
  3. **中间流独立滚动与悬空滚动条去噪**：中间小说正文流（`center-novel-stream`）独立垂直滚动，隐藏原生外部悬空滚动条（`scrollbar-width: none; ::-webkit-scrollbar: none;`），消除卡片与右侧看板之间游离的工业机械线条；
  4. **顶部标头与微光进度条常驻顶端**：将「演化长卷」标头卡片（`stream-top-bar`）作为固定顶层结构与正文滚动区域解耦。标头及底缘的 2.5px 微光渐变阅读进度线（`read-progress-track`）**始终常驻在顶部**，正文卡片向下滚动时从标头下方穿过，进度条随阅读深度平滑生长，永不随滚动滚出视口；
  5. **解除大屏居中限制以全宽贴边**：移除 `.workspace-container` 原有的 `max-width: 1720px` 与居中外边距，在大屏（1920px+）下左右抽屉完美贴紧视口边缘，与顶部 Header 的两端像素级对齐；
  6. **正文与抽屉底色一致性修复**：修复了 `TimelineLogItem` 样式中私自硬编码覆盖的冷白底色 `#f0f3f8`，统一回归全局变量 `var(--neu-surface)`（`#e6e9ef`），消除中间卡片与两侧抽屉的色温色差，恢复新拟态同一材质的光影沉浸感。


![排版细节二次优化：防溢出与数值纯净化](./dev_img/屏幕截图%202026-10-10%20223652.png)

- **暴露问题**：AI 生成的 NPC 社会头衔过长导致文本溢出、角色名字换行；正向好感度携带显式 `+` 号（如 `+28`）略显生硬报表感。
- **优化方案**：为身份标签增加 Flex 优雅截断与悬浮 Tooltip；锁定姓名不可换行；格式化逻辑移除正向数值多余的 `+` 号前缀。

## 2. 核心管线与底层提示词工程演进 (Pipeline & Prompt Architecture)

### 2.1 为什么坚持 Pass 1 + Pass 2 两步解耦？
在系统设计初期，最直观的做法往往是单次 Prompt 让大模型“既计算主角身心状态，又输出文学描写”。但测试表明这会导致严重隐患：
1. **注意力分散与逻辑崩盘**：LLM 在同时兼顾数值逻辑判定（精力增减、物品获取、时间推移、关系演变）与高质量文学描写时，往往顾此失彼。到了推演后期，容易发生幻觉或违背世界因果律；
2. **两步各司其职**：
   - **Pass 1（衡律之神 Arbitrator）**：纯理性逻辑机器。只负责大纲、因果裁决、作息决策、目标增损以及输出合法的 State Delta JSON。不写文学修辞；
   - **Pass 2（见证之神 Storyteller）**：纯文学叙事大师。以 Pass 1 的客观事实骨架（Plot Beat）和感官线索为地基，以第三人称有限视角完成纯粹文学润色。

### 2.2 文风框架与文学技法补丁库
- **引入初衷**：如果不对文风进行专项系统工程指导，AI 写出的文本无论放在什么世界观下，其用词、句式和语气其实都高度雷同（典型的 AI 通用小说腔调）。为了让世界真正生动灵动，系统引入了原创的 12 种世界模拟文学风貌（东方素描、生活轻喜、黑色幽默、戏谑发疯、日常钝痛、感官漫游、慢调光影、沉郁庄严、青涩时光、诡谲志怪、炉火轻奇等，以及自由自适应匹配），用户可根据不同世界观自由切换。
- **文学技法补丁（Writing Patches）**：针对 AI 写作的常见通病注入精准免疫抗体：
  - *小说张力与事件驱动*：严禁整篇文字在死物垃圾上做无意义显微镜描写（如反复捏易拉罐、抠塑料外壳、看尘埃飘落），强制每一段都有事件在实质发生；
  - *主角意志与动机连贯*：严禁无目的空心发呆，角色每一步都受其内核驱使；
  - *客观白描*：用具体动作与现实抉择替代抽象的情绪定性；
  - *活人生态对白*：对话充满试探、机锋与性格棱角，拒绝变成设定解说机器；
  - *拒绝段尾归纳*：严禁在段末以说书人姿态强行升华总结哲理鸡汤。

### 2.3 字数控制的哲学：推荐引导而非死板卡死
- **设计考量**：不同用户对推演的节奏偏好截然不同。有的希望快速高频步进（精炼短切片 300~500 字），有的希望获得正统长篇阅读体验（标准 500~800 字，或深度长卷 800~1200 字）。
- **软约束认知**：在提示词中必须明确，大模型生成内容具有天然的创造性与不确定性，字数限制本质上是“推荐字数 / 期望引导区间”。生成内容受情节密度影响，略多或略少于设定区间属于正常的文学呼吸，系统不宜采取生硬机械的暴力截断。

## 3. 前端视界之外的推演细节 (Hidden Engine Mechanisms)

### 3.1 在场 NPC 多人关系特化（避免“世界围着主角转”）
这是用户在前端界面上看不到、但后端推演管线至关重要的提示词注入细节：
- 当判定当前物理空间有 NPC 在场（或有来客/交谈对象）时，管线会动态注入专属的多人关系特化提示词；
- **核心法则**：坚决避免“全世界围着主角转”的单向独角戏。每位在场角色都拥有独立的生存立场、核心利益与道德底线。事件是由“个人选择—群体反馈”连锁推进的，人人有戏、彼此成局，NPC 绝非单向响应主角的工具人。

### 3.2 动态社交拓扑扩充：新认知角色的自主沉淀机制
- **破除固有小圈子**：在很多模拟器中，主角推演了几百轮后，认识的人永远只有世界初始化时写好的那两三个角色，世界显得死寂狭小。
- **自主识别与深刻印象准则**：在 Pass 1 裁决中，赋予了 AI 自主识别并结识新角色的权限（`relationship_delta.new_npcs`）。同时设定了严格的结识门槛——随口搭话的路人甲、打照面的背景龙套绝不入库，唯有主角对其产生深刻印象、具备明确姓名且拥有后续持续交集潜力的关键人物，才会正式沉淀进主角的人际关系网中。

## 4. 拟真生态与自转节律探索 (Living World & Pacing)

### 4.1 为何在沙盒中引入拟真手机系统？
- **沉浸感必然**：现代与近未来背景下，人的生活早已与手机深度绑定。微信消息、语音、转账记录、朋友圈动态、匿名论坛发帖，是当代人际交往与信息获取最真实的切片；
- **跳出“小说生成器”的思维定势**：WorldSim 的定位从一开始就不是传统的死板网文生成器，而是一个自运转的沙盒世界。既然作为模拟世界，为什么不多做一些跳出常规文本框的、充满趣味与拟真感的探索？

### 4.2 自由续写（智能续写）与真实时间尺度约束
- **续写初衷**：在单步 1 小时或快进时，用户经常会遇到刚刚触发了一件极感兴趣的突发事件，但一旦点击下一步（+1h），AI 往往在段落开头用一两句话把刚才的事草草交代收尾，极度扫兴。智能续写允许用户在不强行跳转时间的前提下，让 AI 就当前焦点事件继续自然推演展开。
- **时间节律与尺度指引**：为了杜绝“时间才过去 1 小时，主角吃了饭洗了澡甚至还拖了个地”的时空膨胀荒谬情节，引擎引入了“完整行动单位尺度”指引，AI 自主研判推进 0.5h、1h 还是半天，铺垫时放慢展开细节，交锋时紧扣危机，维持真实的物理重力感。

### 4.3 突发事件（变数之引）去极端化与世界观自适应
- **早期的偏激教训**：在最初构思突发事件提示词时，为了追求强戏剧张力，提示词编写得过于偏激激进。在实际测试中，甚至出现过普通校园青春背景下，平地冒出一个“神秘杀手暗杀主角”的荒谬出戏情节。
- **优化与自适应**：全面重构了突发事件构思引擎，要求其必须严密契合当前世界观题材（校园、职场、修仙、末日等）与即时微观情境。突发事件（如失物招领、突击检查、暴雨滞留、错收快递、临时调派）的使命是自然打破当前稳态、注入生动波澜，绝非为了冲突而强行摧毁日常世界观。
