# 模块 03：双步推演管线与高保真长程记忆模型规范 (Two-Pass Tick Pipeline)

---

## 1. 架构总览与核心设计原则

系统推演机制的核心铁律是**两步解耦（Two-Pass Decoupling）**与**事务原子性（Transactional Atomicity）**：
- **Pass 1: 裁决与状态推进引擎（Arbitrator Engine）**：专职负责理性裁决。在世界法则约束与生理精力驱动下，判定角色的行为结果、物品损益、地点转移与客观事实骨架（Plot Beat）。
- **Pass 2: 场景小说生成器（Storyteller Engine）**：专职负责文学表达。以严格的第三人称有限视角（Third-Person Limited），将事实骨架转化为富有环境感官沉浸感的小说切片。
- **事务原子性铁律（严禁静默假数据入库）**：单轮推演必须确保 Pass 1 与 Pass 2 **全部成功**方可持久化写入数据库。若任一环节发生调用失败、解析异常或网络中断，后台事务必须立即自动回滚，并在终端记录详细报错，向客户端返回标准化错误码，**绝对严禁使用硬编码假文本进行静默假落库**！

## 2. 60k Token 架构下的三层高保真记忆模型

在现代长上下文大模型（如 64k~128k 上下文）的支持下，系统将单轮推演的 Token 上限放宽至 **60,000 (60k) Tokens** 以内。这彻底解除了对酒馆庞大世界书的字数截断限制，使得记忆模型能够保持极高的文学厚度与叙事连续性。

```
+-----------------------------------------------------------------------------------------+
|                        60k Token 容量下的三层高保真记忆模型                                |
+-----------------------------------------------------------------------------------------+
| Tier 1: Living State Sheet (即时生存状态看板)                         [~500 Tokens]     |
| - 当前虚拟时空坐标、生理属性（健康/精力）、自适应作息画像                               |
| - 动态演化的目标栈（当前目标、前置阻塞、历史已达成）、随身物品清单                       |
+-----------------------------------------------------------------------------------------+
| Tier 2: Deep Working Buffer (深度连贯叙事缓冲池)                      [~15,000 Tokens]  |
| - 保留最近 10 ~ 20 轮连续高精小说正文切片                                                |
| - 确保文学风格、长篇伏笔、人物语气与正在发生的微观动作保持高度连贯                      |
+-----------------------------------------------------------------------------------------+
| Tier 3: Timeline Ledger & Full Lorebook (完整世界书与历史因果长程网)   [~30,000 Tokens]  |
| - 完整静态世界书（Static World Lore）：不作阉割，完整注入架空世界法理、地理与社会规则   |
| - 动态激活世界书（Triggered Lore）：基于当前地点与实体命中全量激活                      |
| - 历史因果长程账本（Timeline Ledger）：基于倒排索引从 SQLite 中多路召回历史重大转折     |
+-----------------------------------------------------------------------------------------+
| 预留生成缓冲 (Generation Headroom)                                    [~2,000 Tokens]   |
+-----------------------------------------------------------------------------------------+
```

### 2.1 各层级记忆职责与流转规范
1. **Tier 1 (Living State Sheet)**：
   始终常驻于 Pass 1 与 Pass 2 的核心输入区，作为不可逾越的状态红线。任何在推演中发生改变的数值必须严格回写该层。
2. **Tier 2 (Deep Working Buffer)**：
   解决传统生成中“过早遗忘前文细节”导致的文风跳跃与动作脱节。通过向 Storyteller 提供最近 10~20 轮正文，模型能够自然承接数个虚拟小时甚至数天前的环境描写、未喝完的咖啡、伤口的隐痛等微观伏笔。
3. **Tier 3 (Timeline Ledger & Full WorldBook)**：
   - **世界书全保真**：完全容纳酒馆卡内万字级别的复杂世界设定；
   - **因果倒排召回**：根据当前场景关键词检索已移出 Working Buffer 的早期重大事件，形成“历历在目”的长线记忆反馈。

## 3. Pass 1: 裁决与状态推进引擎 (Arbitrator Engine)

### 3.1 核心职责与输入输出
- **输入维度**：
  1. 当前 Living State Sheet（含即时精力值）；
  2. 角色自适应作息画像（Circadian Profile）；
  3. 完整静态世界书与当前环境命中的动态世界书条目；
  4. 时间流逝跨度（增量小时数）；
  5. 可选外生触发：若用户点击了“触发突发事件”，系统自主构思的危机事件事实将作为硬输入注入。
- **输出格式**：
  必须为严格合法的 JSON 对象，包含状态增量、生理变化判定、事实骨架（Plot Beat）与环境感官线索（Sensory Cues）。

### 3.3 裁决系统提示词工程指导
提示词应着重强调：
- **逻辑自洽性**：判定基于因果逻辑、物理守恒与角色性格；
- **作息与精力平衡**：若精力严重不足且环境安全，必须判定进入休眠以恢复精力；
- **纯理性输出**：杜绝文学描写，只输出冷峻的事实判断与结构化数据。

## 4. Pass 2: 场景小说生成器 (Storyteller Engine)

### 4.1 核心职责与文学标准
- **输入维度**：
  1. Pass 1 裁决出的全部状态增量、Plot Beat 事实骨架与感官线索；
  2. 角色核心底色与羁绊执念；
  3. Deep Working Buffer（最近 10~20 轮连续正文，确保语调、文风与伏笔连贯）；
  4. 当前场景强相关的世界书背景条目。
- **产出标准**：
  - **第三人称有限视角（Third-Person Limited）**：镜头始终紧随主角的感官与视线，严禁全知旁白；
  - **情节推进与戏剧呼吸（Plot Progression）**：拒绝整篇描写捏易拉罐、抠塑料外壳、看树叶尘埃等毫无剧情价值的微观死物堆砌！文字必须牢牢聚焦于人物的主动抉择、人际碰撞与外部情势演化，确保读者获得扎实的情节获得感；
  - **篇幅控制**：依据选定档位控制字数（精炼 300~500 字，标准 500~800 字，深度 800~1200 字），强制 2~4 个独立自然段落，段落间双换行分隔；
  - **绝对纯净正文**：严禁出现任何状态框（如 ````stat`）、属性增减提示（`+5 精力`）、元数据括号或 Emoji 图标。

### 4.2 文学叙事提示词指导规范
指导 LLM 担任严肃小说创作者：
- **反死物显微镜（Anti-Trivial-Stagnation）**：每一句器物与环境描写必须为【人物处境】、【氛围渲染】与【情节推进】服务，拒绝假精致流水账；
- **活人生态与对话机锋**：在场有 NPC 时展开真实的言语试探与利益博弈，独处时展现深谋远虑与警惕应对；
- **单向时间流逝与防复读**：严格沿时间线向前演进，严禁重复前文已完成的动作与交互。

## 5. 快进推进算法规范 (Fast-Forward Architecture)

为避免粗粒度时间推进时产生无意义的死板模板刷屏，系统快进机制定义如下：
- **完整跨度一次性推演**：快进（+6h 或 +24h）直接将完整的 `total_hours` 注入 Pass 1 与 Pass 2；
- **情节饱满度匹配**：Pass 1 裁决机裁定整段长跨度历程中发生的【关键波折、实质演化与地点位移】；Pass 2 叙事机将其演绎为一段完整充实的小说故事切片；
- **唯一故事切片落库**：快进单次仅产生并落库一条高质量故事切片，绝对杜绝“前半段占位模板 + 后半段重复推演”的冗余日志生成；
- **严格时间解析无后缀**：虚拟时间流转采用精确的 24 小时制与跨日/日号解析器，彻底清洗并禁止任何 `(+Xh)` 拼接后缀。

## 5. 世界模拟沙盒专用文风指引、文学技法补丁与篇幅字数控制规范

本项目为纯粹的【自转虚拟世界沙盒模拟器】，其与传统玩家角色扮演（RP）的核心区别在于：
- **没有 user 角色**：不存在玩家扮演的实体，用户是纯粹的高维观察者；
- **没有外部文本输入**：推演主流程为纯按钮时钟步进，不存在对话输入框或给用户留反应空间的对戏轮次；
- **纯自转客观演化**：角色依据生理精力、作息画像、物理环境与核心执念（Inner Drive）自主做出抉择并推进生活。

基于此架构特化，系统将 Pass 2 叙事机升级为多维可配置的自转世界文学工程引擎：

### 5.2 世界演化物理法则与文学补丁 (Physics & Realism Rules)

系统将世界模拟的严苛物理规律直接固化进双步推演底座：

#### 1. 物理时间与行动预算（Time Scale Realism）
- **行动容量匹配**：依据系统给出的推进时长（如 1h / 6h / 24h），严格匹配角色的物理行动范围。1 小时的时间跨度只能完成一件微小的连续事件（如：吃完一顿饭、检修一个核心、避雨等待）；严禁在短时切片内塞入多幕大起大落的戏剧转折。
- **物理阻隔真实存在**：出行消耗现实时间（步行、等红绿灯、渡河、通勤），严禁跨区域“瞬间移动”。

#### 2. 现实生活底噪（Living Grounding）
- **无目的伴生动作**：角色在独处、等待、疲惫或无聊时，会自然进行伴生动作（发呆、整理器物、洗漱、打扫工坊、盯着水滴发愣）。这是生活底色，不需要推动任何重大剧情。
- **生理节律连续性**：角色的精神状态、体力和饥饿感是连续渐变的。熬夜会反应迟钝、白天会有困倦期、累了会瘫软。严禁“零过渡入睡”或“原地满血刷新”。
- **去职业标签化**：角色的职业与特长仅作为技能储备，严禁成为无时无刻不在展示的行为。闲暇时做日常杂事，绝不无休止空转职业技能。

#### 3. 信息迷雾与独立世界线（Information Isolation）
- **严格视野受限**：角色仅知晓自己亲身经历、被告知或设备接收到的信息，严禁上帝视角预知其他不在场角色的动向与位置。
- **偶遇的概率法则**：除非身处极其封闭的微型空间，否则在开放世界中严禁刻意编造低概率的“刚好撞见熟人”。
- **社交摩擦常态**：不在场的 NPC 有自己的工作、生活与作息，不会时刻围绕主角转。未收到回复的信件、未归的同伴是生活常态，不需要每次都升级为情感冲突。

#### 4. 推进结算与突发事件标准（Progression Logic）
- **长跨度平淡结算**：长跨度快进（6h/24h）无外部突发事件介入时，优先结算日常起居、杂事与生理恢复，微缩白描记录平淡流逝，严禁凭空捏造虚假狗血意外。
- **突发事件触发标准**：必须源于既有环境与前置行为的合理衍生（如零件承压过载开裂、油灯燃尽、巡逻队依照既定航线逼近），严禁机械降神式的虚假空降。

### 5.3 篇幅与字数控制档位 (Word Count & Pacing Tiers)

支持精细化字数约束与段落呼吸感控制：
- **精炼短切片（`concise`）**：300 ~ 500 字，节奏紧凑凌厉，聚焦单一核心动作，适合高频步进。
- **标准文学切片（`standard`）**：500 ~ 800 字（推荐默认），场景铺陈、动作分镜与情绪潜流均衡完整。
- **深度长卷切片（`deep`）**：800 ~ 1200 字，电影级细密运镜与多重暗涌交织。
- **自定义区间（`custom`）**：自由配置 Min 与 Max 字数阈值。
- **前文防复读与时间单向推移律令**：严格禁止重复前序切片中已完成的动作、意象、开篇句式与道具交互，镜头时间单向向前推进，专注实现本轮 Plot Beat。
- **段落呼吸与双换行排版律令**：强制划分 2~4 个独立自然段落，单段 120~200 字，段落间必须使用双换行符（空行）严格分隔，严禁输出无换行的巨型文字墙。前端阅读器基于换行符自动切分为独立段落进行首行缩进与垂直间距排版。

### 5.5 SSE 实时流式传输与楼层神性交互规范 (Real-Time SSE Streaming & Divine Presentation)

为了消除长文本推演时用户的等待焦虑，并彻底摆脱冷冰冰的机械式“Pass 1 / Pass 2”工程术语，系统在保持双步解耦与事务原子性的前提下，提供了沉浸式神性管线与最新楼层自适应交互：
1. **流式端点**：
   - `/api/v1/sim/step-stream`
   - `/api/v1/sim/continue-stream` (智能续写流)
   - `/api/v1/sim/fast-forward-stream`
   - `/api/v1/sim/trigger-incident-stream`
2. **事件流协议与神性称谓规范**：
   - `event: status`：返回当前执行阶段与神性文案：
     * `stage: pass1`：`【衡律之神】正在权衡因果法则与身心节律...`
     * `stage: pass2`：`【见证之神】正在以有限视角编织时空切片...`
     * `stage: incident_conceive`：`【变数之引】正在结合世界题材构思突发变故...`
   - `event: pass1_done`：【衡律之神】裁决完毕，先发传递虚拟时空、地点与客观事实骨架（Plot Beat）；
   - `event: chunk`：【见证之神】输出的实时文本增量 Token (负载兼容 `text` 与 `delta` 字段)，前端即时以打字机模式逐字上屏；
   - `event: finish`：推演完成并成功提交数据库事务，返回完整 `StepTickResponse`；
   - `event: error`：执行异常或中断时回滚并返回结构化错误码。
3. **最新楼层沉浸式交互规范（屏幕顶部无遮挡）**：
   - **移除屏幕顶部横幅**：推演期间彻底移除全屏顶部的浮动状态条，视线无干扰；
   - **最新楼层即时挂载**：触发推演后，时间线最新楼层立即挂载（第 N 刻卡片），平滑滚动至视口中央；
   - **非流式模式（`enable_stream_display = false`）**：最新楼层直接展示优雅拟物动效的“生成中...”，不暴露中间环节；
   - **流式传输模式（`enable_stream_display = true`）**：在最新楼层依次呈现神性两步回复：
     * 阶段一：展示【衡律之神】因果权衡中（带呼吸动效）；
     * 阶段二：衡律之神裁决完成，楼层先呈现【衡律之神·因果裁决】的事实骨架回复；
     * 阶段三：紧接着展开【见证之神】正文创作，逐字打字机流式输出纯文学正文；
     * 定稿落库后：临时楼层平滑无缝切换为正式持久化卡片，下方折叠面板保留【衡律之神】因果骨架与即时状态增量检视。

### 5.6 手机与社交网络交互拟真规范 (Phone & Social Messaging System)

针对现代、近现代或具备通讯网络背景的世界观，系统支持在 Pass 2 注入手机交互提示词，将酒馆标准手机正则语法内化为原生视觉卡片：
1. **系统全局开关 (`enable_phone_simulation`)**：
   - 在【系统设置】（`SystemConfigModal`）中配置是否开启“手机与社交网络交互拟真”；
   - 支持在推演请求的 `SimulationPromptConfig.enable_phone_simulation` 中单次动态覆盖。
2. **Pass 2 提示词注入语法标准**：
   - 即时私信消息：`[消息-角色名]: 消息正文`
   - 语音消息：`[语音-角色名|时长]: 语音转写文字内容`
   - 定位分享：`[定位-角色名]:[具体地名]` 或 `[定位-角色名]:[描述-具体地名]`
   - 转账消息：`[转账-角色名]: 金额 (用途备注或附言)`（如 `[转账-陈叔]: ¥5000.00 (首期调查勘察经费)`，界面备注栏自动展示附言）
   - 朋友圈动态：`<朋友圈>\n[发布:角色名]: 正文 {{图片描述}}\n[点赞]: A, B\n[评论:C]: 内容\n</朋友圈>`
   - 网络论坛/社区热帖：`<论坛>\n[板块:名称]\n[贴子:发帖人|标题]: 主贴正文 {{图片描述}}\n[热度:浏览量 · 点赞量]\n[状态:锁定]\n[评论:回帖人]: 内容\n</论坛>`
3. **红线守则**：
   - 绝对无 Emoji 规范：严禁在手机消息、评论或正文中生成任何 Emoji 图标；
   - 保持第三人称有限视角沉浸感，绝不机械堆砌，仅在角色真实看手机或联络时自然生发。

### 5.7 自由续写与动态时间切速准则 (Dynamic Pacing & Autonomous Time Scale)

为了防止模型机械式地按固定 1 小时进行流水账式平铺直叙，系统引入由 AI 自主裁决时间尺度的【自由续写】管线：
1. **场景目标动态切速**：
   - 铺垫阶段放慢笔触捕捉环境氛围、人物细微动作与情绪暗涌；
   - 冲突爆发时加快推进切速，紧扣危机与关键抉择；
   - 冲突收束或余波阶段回稳沉淀，避免单一节奏产生审美疲劳；
2. **完整行动单位尺度**：
   - 单轮次演化以“一个完整行动单位”为基准尺度（可为 30 分钟、数小时、半天甚至数日），拒绝死板的一分钟推进；
3. **防冗余与不过早跳过平衡**：
   - 当场景已充分展开、缺乏有效变化且无待回应的紧迫互动时，自然略过重复琐事与冗余等待，果断跃迁至下一个合理事件发生的时间点；
   - 当存在未完成的重要互动、待主角决定的关键选择或尚未处理的即时冲突时，绝不擅自跳过或突兀加速推进；
4. **时间因果与时钟闭环**：
   - 结合基准虚拟时钟校准“方才、昨天、数日前”等相对表述；
   - 若时间信息不明确，沿用既有时间线合理推断，绝不擅自重置或制造时间线冲突。

### 5.8 在场多角色横向区分与群像共驱法则 (Multi-Agent Co-Driven Dynamics)

当现场存在已结识且在场的 NPC（`is_present = 1`）时，系统自动在 Pass 1 与 Pass 2 动态激活群像多角色共驱指令：
1. **多角色共驱，打破单主角垄断**：
   - 关键角色均具备独立立场、核心利益与行事底线，事件由“个人选择—群体反馈”连锁推进；
   - 角色在合作、试探与冲突中持续改写关系结构，确保“人人有戏、彼此成局”；
2. **横向比较与性格防火墙**：
   - 即使身份、阶层或类型相似，也严格区分其权力来源、核心欲望、处事逻辑、道德边界与情感防御方式；
   - 规划角色面对同一事件时截然不同但符合自身经历的判断与选择；
3. **语言肌理与微动作具象化**：
   - 为每名在场角色确立不同的语言节奏、关注重点、行为习惯、压力反应及表达亲疏的方式；
   - 拒绝所有角色千人一腔，通过眼神躲闪、语调停顿或肢体小动作展现其独特防御机制。

### 5.9 题材自适应突发事件引擎规范 (Genre-Adaptive Inciting Incident Engine)

1. **题材自适应铁律**：
   - 突发事件必须与当前世界观题材（校园青春、都市职场、古风修仙、科幻调查等）与微观现实情境高度契合；
   - 坚决杜绝生搬硬套脱节的激进仇杀、杀手暗算或血腥暴力（如严禁在校园背景中突兀空降职业杀手）；
   - 校园背景聚焦于：突击检查、失物招领、暴雨滞留、意外传闻、黑板神秘留言、社团变故等自然生活波澜；
2. **用户选择双轨支持**：
   - 支持一键由 AI 结合题材与世界书自主构思；
   - 支持用户通过弹窗自定义输入指定事件作为主导因注入推演。
