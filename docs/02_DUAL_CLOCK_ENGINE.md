# 模块 02：双轨驱动时钟引擎与自适应作息机制规范 (Dual-Clock Engine)

---

## 1. 概述与设计哲学

双轨驱动时钟引擎（Dual-Clock Engine）是整个系统在“完全脱离用户输入交互”状态下持续自律演化的时间引擎。它提供两种协同推进模式：
1. **真实时间同步模式（Real-Time Sync）**：与现实物理流逝对齐，后端调度器每小时自动 Tick 一次，负责角色平缓的日常生活推进与离线长间隔自适应折叠。
2. **沙盒自由推演模式（Virtual Sandbox）**：提供给用户的“上帝观察台”，仅包含纯按钮操控（+1h 微步进、+6h 阶段步进、+24h 跨日跃迁、触发突发事件），无任何用户文本输入框。

---

## 2. 精力与环境驱动的自适应作息与睡眠模型

系统坚决抛弃固定的机械作息时刻表，改由**角色作息画像（Circadian Profile）**、**即时生理精力（Stamina）**与**环境可休眠度（Environment Affordance）**三维协同动态判定。

### 2.1 作息判定的三维协同决策树

```
                                  [Tick 周期开始]
                                         |
                                         v
                     +---------------------------------------+
                     | 查询角色当前精力值 (Stamina, 0~100)    |
                     +---------------------------------------+
                                         |
               +-------------------------+-------------------------+
               | 精力极度匮乏 (< 20)                               | 精力充沛或适中 (>= 20)
               v                                                   v
+-----------------------------+                     +-----------------------------+
| 强制进入寻找休息地点裁决:   |                     | 检查当前虚拟时间与作息画像:  |
| - 检查当前环境是否可睡?     |                     | 是否处于画像的倾向睡眠窗口?  |
|   (室内/床榻/安全载具/露营) |                     +-----------------------------+
+-----------------------------+                                    |
               |                                                   |
       +-------+-------+                                   +-------+-------+
       | 是            | 否                                | 是 (且精力<50)| 否 (或精力充沛)
       v               v                                   v               v
+--------------+ +---------------------+             +--------------+ +--------------------+
| 进入深度休眠 | | 强行熬夜支撑:       |             | 自然准备就寝 | | 正常清醒活动:      |
```

### 2.2 影响睡眠决策的核心要素规则
1. **作息画像弹性（Chronotype Flexibility）**：
   - 角色每天的睡眠起点具有自然的波动范围（±1~2 小时），受到当天白天经历事件的刺激程度影响（例如刚经历激烈战斗或重大发现时，即便到了入睡窗口也会兴奋或警惕推迟睡眠）。
   - 特殊体质豁免：对于亡灵、构装体、无休眠生物，其作息画像标记为无休眠体质，精力衰减与恢复与普通睡眠解耦。
2. **环境可休眠度（Environment Affordance）判定**：
   - **高适宜环境**：自家庭院、租住旅社、安全盟友营地、长途载具卧铺。当角色精力低于 45% 且进入此类环境时，优先自主选择休息。
   - **低适宜但可应急环境**：列车/飞机客舱座椅、废弃屋棚檐下、避风岩洞。角色只有在精力低于 20% 时才会在此短暂浅睡或打盹。
   - **严禁休眠环境**：暴雨泥泞中的逃亡荒野、有敌意巡逻的街道、交火现场。角色绝不会在此就寝，而是触发“对抗困意、搜寻庇护所”的目标行为。

## 3. 离线长间隔与断点自适应补偿策略

当用户长期未打开服务，或后端定时器在中断后恢复时，系统时间与角色状态产生较大时差。处理原则是：**杜绝串行狂刷数十次完整 LLM 推演，亦杜绝状态突变脱节，采用两阶段折叠推演**。

### 3.1 补偿逻辑设计
- **短间隔（1 ~ 3 小时）**：
  采用紧凑循环逐小时顺推，完整走 Pass 1 与 Pass 2，保留全部小说细节。
- **中间隔（4 ~ 24 小时）**：
  - **阶段 A（历史大跨度折叠）**：调用一次轻量级折叠判定。根据角色作息画像计算期间涵盖的清醒工作与睡眠时段，粗粒度推进生理状态（例如消耗干粮、恢复精力、推进地点行踪），生成 1 条宏观编年史摘要写入历史事件账本；
  - **阶段 B（最近现场精细推演）**：针对最后 1 个小时，在折叠后的状态基准上，执行标准的高精度双步推演，产出最新小说正文切片。
- **超长间隔（> 24 小时）**：
  系统限制最大演化折叠上限（例如最多折叠 3 天），将角色推移至最新合理情境（如完成了一次长途跋涉或在一个新据点安顿下来），避免数值无限归零或剧情无限发散。

## 4. 沙盒自由推演模式（纯按钮与自主演化控制规范）

沙盒模式是全知观察者加速世界演化的核心交互面板。

### 4.1 核心操作控制设计
操作区包含功能明确的新拟态交互控制：

1. **`续写` 按钮（智能续写 / 动态切速演化）**：
   图标 `material-symbols:auto-stories`。直接承接前序切片顺流推进，彻底杜绝机械的一分钟或一小时死板步进；由 AI 依据剧情张力、当前互动与事件成熟度自主裁决时间尺度（可为 30 分钟、数小时、半天或进入下一关键事件节点），维持“起—扬—收”的戏剧呼吸。
2. **`+1h` 步进按钮**：
   图标 `line-md:chevron-right`。指定推进 1 虚拟小时，执行精准的单步 Pass 1 裁决与 Pass 2 文学切片。
3. **`+6h` 阶段快进按钮**：
   图标 `line-md:chevron-double-right`。手动推进 6 虚拟小时，跨越一个生活阶段（如由清晨直达日暮，或由深夜直达黎明）。
4. **`+24h` 跨日跃迁按钮**：
   图标 `line-md:chevron-triple-right`。推进 1 整天，自动折叠日常琐事，重点描绘该日核心转折切片。
5. **`触发突发事件` 按钮（Trigger Inciting Incident）**：
   图标 `material-symbols:crisis-alert`。
   点击后唤出新拟态事件弹窗，支持两种触发途径：
   - **AI 自主衍生（题材自适应）**：结合当前世界观题材（校园日常、都市职场、古风修仙、科幻调查等）、世界书法则、当前地点与即时情境，构思高度契合题材的意外插曲或变故，坚决杜绝生搬硬套脱离背景的极端仇杀或恶性阴谋；
   - **用户自定义输入**：允许用户主动注入指定的外部变数事件（如“教导主任突击检查自习室”、“储物柜发现求助信”），作为最高主导因注入 Pass 1 裁决。

### 4.2 调度并发控制与状态互斥锁
在实现时，AI 开发者必须在后端针对每个 `character_id` 引入异步锁（如 `asyncio.Lock`）：
- 当 APScheduler 自动定时推演与用户界面上的快进按钮同时触发时，互斥锁确保上一轮推演完全落库后下一轮才可进入；
- 避免同一个角色的状态、背包与故事流水发生写写冲突。
